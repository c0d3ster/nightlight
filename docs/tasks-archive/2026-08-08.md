## #2 [stack: core-loop] Design and implement fresh-subprocess-per-task execution model

PR: #24 (`overnight/2026-08-06/01-fresh-subprocess-per-task`)

Restructured `overnight.sh` to dispatch one fresh `claude -p` subprocess per open task instead of one continuous session across a repo's whole TASKS.md. Added `split_tasks()`, `docs/stack-notes/<stack>.md` handoff (append-only, first task in a stack creates it), `resolve_base_branch()`, and the `TASK_RESULT: #<n> status=... branch=... pr=... note="..."` contract each task subprocess emits for housekeeping. `stats/<repo>.json` now also tracks `total_cache_read_tokens`/`total_cache_creation_tokens` per run.

Note: the task's NEEDS HUMAN acceptance criterion (a supervised `--limit 2` trial across two stacks, comparing cache-read volume against the 2026-08-06 c0d3ster baseline of 42.8M tokens / $16.61 for 2 tasks) was not run as part of PR #24 itself. An initial spot-check trial run by the task owner after merge showed a notably lower cost, but on a run with different task complexity than the baseline, so it isn't a clean comparison. Further trials are ongoing outside of TASKS.md tracking; archived as complete per the task owner's call, not because the trial is fully conclusive.
